Item 4 reCAPTCHA Disclaimer Text on Create Account, Login & Forgot Password

Developer Status

"reCAPTCHA text appears automatically once reCAPTCHA is enabled... confirming the US domain is allowed on the reCAPTCHA key before enabling to avoid login failures."

QA Technical Finding & Assessment: VALID DEV RATIONALE

• On AU Live, Magento's core Google reCAPTCHA Knockout module (field-recaptcha) dynamically injects the disclaimer text above the submit button once the module is active.

• On US Staging, reCAPTCHA is currently disabled for customer forms. This is a critical security precaution: enabling reCAPTCHA before whitelisting mcstaging2.globewest.com in Google Cloud Console would trigger ERROR: Invalid domain for site key, entirely blocking login and account creation across the staging environment.

• QA Status: Kept in In Progress until developer/DevOps whitelists the domain and switches the module on.

Item 5 Create Account: Password Field First Click Focus
ℹ️ CLARIFICATION PROVIDED
Initial Reported Defect

Cursor does not focus on password field on the first click (Screen Recording).

Developer Response

"Couldn't reproduce — could you confirm browser, version, device, and whether it still happens in a private window with nothing pre-filled?"

Technical DOM Inspection: • Element: <input type="password" id="password" class="input-text" autocomplete="off"> • CSS Computed: pointer-events: auto, z-index: 2, cursor: text • Element at point (x, y): Returns the exact <input> tag (no invisible overlay or floating label blocking it).
Root Cause Clarification for QA & Dev:

1. Password Manager / Keychain Interception: In normal browser windows (Chrome / Safari / Edge), clicking into a type="password" field triggers the browser's native Password Manager autofill / "Suggest Strong Password" popup. This native browser OS modal intercepts the first click event.

2. Magento Password Strength Meter: Magento's password-strength-meter.js attaches listeners on the field which initialize on initial focus.

3. Guidance: Confirm to developer that this occurs in standard browser windows with autofill/password management enabled. In clean Incognito/Private sessions, direct DOM clicks focus on click 1.

Item 6 Responsive (iOS / Safari): Auto-Zoom on Input Field Focus
ℹ️ CONFIRMED AU PARITY (14px FONT)
Initial Reported Defect

On iOS Safari, tapping into form inputs causes the browser to automatically zoom in (OzQecI30ZP, 0fpuzQUbaK).

Developer Response

"This is expected iOS behavior since our fields are 14px, same as live AU."

Computed Style Verification: • US Staging Inputs: font-size = 14px (prefix, firstname, lastname, email, password) • Live AU Baseline: font-size = 14px (identical on all inputs) • Viewport Meta: <meta name="viewport" content="width=device-width, initial-scale=1">
Technical Explanation & Decision:

• WebKit / iOS Safari Behavior: Apple's iOS Safari forces an automatic viewport zoom on any input whose computed font-size is under 16px. Because AU Live is designed with 14px inputs, Live AU exhibits the exact same auto-zoom behavior on iOS.

• Ticket Mandate: "Match AU, no redesign required." Developer is correct that US behavior is 100% identical to live AU baseline.

• Optional Mobile Enhancement: If the team wants to eliminate iOS auto-zoom without redesigning desktop, the developer can add: @media screen and (max-width: 768px) { input, select, textarea { font-size: 16px !important; } }.
